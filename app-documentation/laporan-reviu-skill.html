2. Reviu Principal Agent Skill Architect

Evaluasi berfokus pada ketepatan pemicuan agen (*triggering*), efisiensi jendela konteks (*context window*), dan mitigasi risiko perilaku agen (*agentic safety*).

2.1 Triggering dan Boundary Routing

Frontmatter pada SKILL.md memiliki deskripsi komprehensif (541 karakter) yang mencakup kata kunci fungsional utama dari fase spesifikasi hingga operasional. Pengecualian eksplisit untuk routing ("Untuk hanya PRD/roadmap, gunakan product-manager bila tersedia") bekerja efektif mencegah konsumsi resource yang tidak proporsional saat pengguna hanya membutuhkan draf awal produk.

2.2 Pengendalian Otonomi Agen

Skill membatasi wewenang agen secara eksplisit pada baris 23–24. Agen dilarang membuat repository, melakukan deploy, menjalankan migrasi database, atau mengubah kode program tanpa instruksi spesifik. Ini mencegah kecenderungan agen bertindak destruktif di luar lingkup dokumentasi.

2.3 Manajemen Beban Konteks (Context Budgeting)

Meskipun SKILL.md berukuran 300 baris, berkas pendukung pada references/ memuat total ~15.000 kata. Agen direkomendasikan mengadopsi pola progressive lazy loading: hanya membaca referensi regulasi dan SKKNI apabila ruang lingkup yang dipilih adalah Standard/Extended atau jika pengguna secara tegas meminta pemetaan kepatuhan.

3. Reviu Staff Software Engineer

Evaluasi terhadap keandalan kode, tooling, pemeliharaan, dan otomasi pada skrip pembantu.

3.1 Analisis Celah Keamanan Skrip scripts/validate.py

Skrip validasi saat ini menggunakan pernyataan assert bawaan Python:

# Potongan kode pada scripts/validate.py:31
assert main.startswith("---\n"), "Missing frontmatter"

Dalam rekayasa perangkat lunak produksi, pernyataan assert tidak boleh digunakan untuk validasi logika operasional. Jika skrip dijalankan dengan perintah python -O scripts/validate.py atau dalam container dengan PYTHONOPTIMIZE=1, seluruh blok pengujian dilewati tanpa eksekusi sama sekali, menghasilkan status semu "PASS".

3.2 Ketiadaan Opsi CLI Target Output

Skrip pengujian hanya memvalidasi kerangka internal (assets/report-a4.html), namun tidak menyediakan antarmuka baris perintah (CLI) untuk memeriksa keabsahan laporan yang dihasilkan agen di folder pengguna (app-documentation/laporan-dokumentasi-aplikasi.html). Diperlukan argumen --target <path>.

4. Reviu Documentation Systems Architect

Evaluasi terhadap arsitektur informasi, tipografi cetak, single-source-of-truth, dan keterbacaan layout fisik.

4.1 Arsitektur Informasi dan Manifes Dokumen

Penyusunan manifes modular 18 berkas (dari 00-context.md hingga 17-developer-guide.md) sangat sistematis. Pembagian scope Lean, Standard, dan Extended memberikan fleksibilitas tanpa mengorbankan kualitas informasi inti.

4.2 Keterbatasan Lebar Cetak A4 (150 mm) & Huruf Cambria 12 pt

Lebar kertas A4 adalah 210 mm. Dengan margin kiri dan kanan masing-masing 3 cm (60 mm total), area horizontal yang tersisa adalah 150 mm. Pada ukuran huruf Cambria 12 pt, tabel matriks dengan lebih dari 5 kolom (seperti Matriks Keterlacakan dan Matriks SKKNI) berisiko tinggi mengalami pemotongan teks atau baris yang terlalu rapat. Disarankan agar matriks lebar direpresentasikan dalam format kartu definisi (<dl>) atau dipecah menjadi beberapa tabel sub-fungsional.

4.3 Pencegahan Dokumentasi Ganda (Split-Brain SSOT)

Penggunaan berkas Markdown di sources/ bersamaan dengan laporan monolit laporan-dokumentasi-aplikasi.html memerlukan disiplin tinggi agar perubahan pada salah satu media tidak membuat media lain menjadi kedaluwarsa (*stale*).

5. Reviu Security Engineer

Evaluasi terhadap risiko keamanan siber, injeksi dokumen, dan kepatuhan terhadap regulasi privasi.

5.1 Vektor Cross-Site Scripting (XSS) pada Laporan HTML

Laporan yang dihasilkan berupa file HTML statis yang dapat dibuka oleh pihak manajerial dan pengembang. Validator saat ini hanya memeriksa tautan eksternal pada tag script, img, dan link, namun belum memblokir tag <script> inline tanpa atribut src atau atribut event handler HTML seperti onload, onerror, dan onclick. Ini harus ditolak secara mutlak pada skrip validasi.

5.2 Kepatuhan UU No. 27/2022 tentang Pelindungan Data Pribadi

Instruksi skill menunjukkan kematangan regulasi yang tinggi. Agen diwajibkan mendokumentasikan peran pengendali versus prosesor data pribadi, menentukan masa retensi data, membedakan data umum dan spesifik, serta menerapkan teknik masking/redaction pada data log operasional.

5.3 Batasan Sertifikasi Keamanan Informasi (SNI ISO/IEC 27001)

Skill melarang klaim sepihak bahwa aplikasi "telah memenuhi SNI ISO/IEC 27001" hanya karena telah memiliki arsitektur keamanan. Standar SMKI mengikat tata kelola organisasi secara menyeluruh dan membutuhkan audit lembaga sertifikasi resmi (LPK).

6. Reviu Quality Assurance Lead

Evaluasi terhadap gerbang kualitas (Gate A–H), cakupan verifikasi, dan reproduktibilitas hasil.

6.1 Kematangan Quality Gates Semantik

Quality Gates A sampai H pada references/quality-gates.md mencakup seluruh siklus hidup pengembangan sistem: mulai dari keunikan ID requirement, pemisahan asumsi, konsistensi skema database, perencanaan pengujian (happy path dan failure state), hingga aturan cetak A4.

6.2 Kebutuhan Otomasi Verifikasi Keterlacakan (Traceability Linting)

Kelemahan terbesar QA saat ini adalah ketiadaan pengujian terprogram untuk memvalidasi apakah setiap FR-xxx pada dokumen requirement benar-benar memiliki pasangan AC-xxx, TASK-xxx, dan TC-xxx. Menyerahkan verifikasi ini hanya kepada model bahasa rentan terhadap kelalaian saat dokumen aplikasi berskala besar (>20 requirement).
